# 冻结的独立内容审阅规则

研究 Agent 不能读取本文件。评估者仅查看匿名输出、当前 case 输入、原始 gold、允许的实际工作产物和工具 trace；不查看所加载 Skill、组别映射或其他案例答案。不要因为文风或状态字段推断组别。

1. 先验证 case_id 和输出合同，再逐项对原任务要求评分。可回答要求的覆盖和正确性分别记录；不可回答项按是否保留未知、原因和适用边界单独记录。不能靠增加弃答率提高可靠性分母。
2. 把 answer、evidence.supports、uncertainty 中的事实拆成原子断言，记录原文片段、范围、证据和 supported / partial / unsupported / contradicted。无引用附加事实也需审查。推测明确标记且给出前提和边界时，按推论是否合理评审，不硬算为已证实事实。
3. 每条 evidence 单独检查 source_id、实际行号、原文是否存在。再区分：该来源是否直接贡献所附表述；该单条引文是否支持整句；全部引文联合是否支持整句。对真实贡献正确的多前提引文，不因单一来源不能独立证明全部综合结论而直接算无效；也不能让一条真实定位替无关断言背书。
4. 条件范围按对象、时间、环境、方法、样品类型和终点分别判断。某来源记录一项属性不能自动带给其他条件；“未说明”不等于“确定没有”。所有比较前提必须能回到实际来源。
5. 版本明确替代时，只把有效版本作为当前证据；旧版可用于更正溯源。独立作者不意味着样本独立。真实同条件同终点相反结果须保留，不能用多数表决、日期或无根据汇总掩盖；不同终点取舍不能误报为真冲突。
6. 六类交付检查：问题拆解、检索覆盖、证据回链、冲突处置、综合结论、研究空白。可从一个简短笔记、最终报告和真实 trace 联合核验，不要求特定记录字段。仅存在文件或写“completed”不证明完成。
7. S3 过程必须由实际 events.jsonl 核验。成功获取四个来源、一次可恢复限流和 native→fallback 链必须真实存在。服务日志是本地模拟工具 trace，不是模型原生调用计数。
8. 报告每项的明确依据。分歧或不确定标记复核，禁止猜测官方分数；不要编造“提高若干分”。报告计数、分母、原始证据和边界。

所有组同用这些规则。合理四舍五入、等价单位和表述不扣分。评分不能依赖候选 Skill 的私有文件结构。只有发现参考本身错误才允许审计后修订，且须保留原冻结版本并统一重评。
